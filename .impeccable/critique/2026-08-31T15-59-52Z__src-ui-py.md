## Design Specificity Verdict

ShiftPress feels authored for this product in structure and interaction. The mirrored Night/Day panels, today/next-day defaults, independent scopes, shift colors, concrete manifest, and count-bearing print action belong to the schedule handoff rather than a generic form.

The deterministic detector returned an empty JSON array with exit code 0 and no rule locations. This is not proof of native UI quality: the detector is web-oriented and has no Tkinter-specific rules. Browser overlays were inapplicable because `src/ui.py` is not browser-renderable, and `docs/screenshots/main.png` is absent, so no runtime visual inspection was available.

## Overall Impression

The selection model is clear, low-risk, and unusually specific to the operator's real job. The largest opportunity is to make readiness and completion as truthful as selection: green state, 100% progress, and successful completion currently appear before the system has earned them.

## What's Working

1. Independent Night and Day intent is exceptionally legible through symmetric controls, separate dates, and separate counts.
2. The manifest translates settings into paper consequences with numbered scopes, document counts, and the target printer.
3. Setup disclosure and smart Night-today/Day-tomorrow defaults keep repeat use fast without hiding the print scope.

## Priority Issues

### [P1] Progress and completion can state something untrue

Progress is advanced before each Word call returns, and `Complete!` is applied before failures are evaluated. Show the active item separately, advance completed progress only after Word returns, and finish in distinct success, partial-failure, and cancellation states.

Suggested command: `$impeccable harden`

### [P1] Known-invalid runs remain actionable and readiness is implied too early

Empty selection, invalid ranges, missing printer, and missing folders do not disable Print. Green `Selected` state appears before preflight. Disable locally invalid runs, name the blocker inline, keep selection neutral until preflight, and show an explicit checking state.

Suggested command: `$impeccable harden`

### [P2] Setup and printer status are ambiguous or stale

`Templates configured` means only that both strings are non-empty, and the no-printer message is not refreshed when availability changes. Summarize Day, Night, and printer separately, scope warnings to enabled shifts, and make availability status dynamic.

Suggested command: `$impeccable clarify`

### [P2] Keyboard and accessibility states are not explicitly protected

Custom dark styles have no tested focus-visible contract, tooltips are hover-only, and Setup focuses the window instead of the first control. Add explicit focus maps, useful focus placement, Escape behavior, access keys, and text alternatives for tooltip-only information.

Suggested command: `$impeccable audit`

### [P2] Long and degraded states are insufficiently hardened

Printer and manifest values do not have a clear wrapping strategy. If `tkcalendar` is missing, the shift panels are absent but the action area can remain interactive. Wrap long workstation values and replace the action area with a disabled dependency-error state when date controls cannot load.

Suggested command: `$impeccable harden`

## Persona Red Flags

**Alex, power user:** The default run is fast, but no global accelerator or mnemonics exist, known dates cannot be typed, and Setup has no keyboard-first focus target.

**Jordan, first-timer:** Green `Selected` plus `Templates configured` reads as permission to print, yet the first authoritative correction may be a modal after clicking Print. No visible help explains template naming or what configured guarantees.

**Sam, keyboard/low-vision user:** DateEntry has keyboard affordances and state is not color-only, but focus visibility depends on theme defaults, hover tooltips are inaccessible, and dynamic status is not explicitly announced.

## Minor Observations

- The blue primary action has a Day-amber border, weakening its shift-neutral meaning.
- Body/control text uses the Display face rather than reserving it for headings.
- `1 operation(s) failed` should be properly pluralized operator language such as `1 schedule failed`.
- The empty progress bar and 0% can remain hidden until validation begins.
- PRODUCT.md references `docs/screenshots/main.png`, but that file does not exist.

## Questions to Consider

- Does green mean selected or verified ready?
- Is a job complete when Word begins, when Word returns, or when the spooler accepts it?
- Should Setup describe the whole installation or only what the enabled shifts require?
- Would strict typed dates make distant repeat work faster without weakening safety?
